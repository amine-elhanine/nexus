mode 02 — code

An engineer with a supervisor,
not a copy machine

Code mode pairs a long-horizon agent with a verify supervisor. It plans before touching anything, implements with real tools, then checks its own diff — and repairs what fails — before you ever see “done”.

  • Plan / Ask / Auto — from read-only exploration to fully autonomous (40/100/150-step budgets)
  • Verify-and-repair loop: typecheck + test cascades, up to 5 self-repairs in Auto
  • 20-deep checkpoints, per-hunk discard, Nexus-only commit reset — your history untouched
  • Isolated git worktrees per session: merge to main, abort, or discard cleanly
  • Repo map + persistent symbol index built for large codebases
  • Respects your rules: AGENTS.md, CLAUDE.md, .cursorrules, .nexus rules
  • Plan artifacts with one-click “Approve & Execute”
  • Visible subagent fleet: researchers, testers, security reviewers

▸ step 04 — trust

Powerful on purpose.
Guarded by default.

Approval gates

Risky commands open a modal: Deny · Allow once · Allow for session. Silence for 120 s means deny.

Deny backstop

~25 destructive patterns are always refused — disk wipes, fork bombs, registry deletes, boot tampering.

Read-only Plan mode

Plan mode hard-refuses writes, edits, shell and MCP. Explore a codebase with zero side effects.

Secrets stay secret

Keys encrypted with the OS keychain; terminals get scrubbed env; daemons run on a strict allowlist.

No cloud middleman

Your code goes only to the provider you configure. State is a local file; transcripts are local JSONL.

Custom policies

.nexus/permissions.json or nexus.permissions in package.json — allow / ask / deny globs per project.

The honest fine print: Nexus runs real shell commands and edits real files — that’s the point. Its safety model is approvals + deny-backstop + encryption, not a sandbox. Review the Diff tab before keeping changes.

frequently asked

Questions, answered

Do I need my own API keys?

Yes — Nexus is bring-your-own-key across 15 providers. Add them in Settings → AI Providers (encrypted at rest) or via environment variables. Prefer fully local? Point Nexus at Ollama and the offline embeddings fallback — no cloud calls at all.

Is my code or my documents sent anywhere?

Only to the LLM provider you configure — there is no Nexus cloud, no telemetry service, no middleman. App state lives in one local JSON file; transcripts are local JSONL; secrets are encrypted by your OS keychain.

How is this different from Copilot or Cursor?

Those are autocomplete-first editors. Nexus is a full autonomous agent for your whole desktop: it plans, executes in real files and shells, verifies its own work, repairs failures, hands you per-hunk undo, and extends beyond code — documents, research, memory — in the same app.

Can the agent destroy my repository?

It can make changes — that’s the point — but you’re guarded: approval gates on risky commands, a hardcoded deny backstop for destructive patterns, read-only Plan mode, isolated git worktrees, 20-deep checkpoints, per-hunk discard, and Nexus-only commit resets that never touch your own commits.

What is the groundedness gate in Notebook?

Every Notebook answer is scored 0–10 against the evidence retrieved from your sources. If your files don’t cover the question, Nexus tells you “not in your files” and refuses rather than guessing. Citations open the exact source passage.

Which platforms are supported?

Windows 10 and 11 (64-bit) — available as an auto-updating NSIS Setup or a standalone Portable exe. You can also build from source anywhere Node.js 20+ runs.

How do updates work?

The Windows Setup ships with electron-updater: a pill in the app shows download progress and restarts to apply. Portable builds re-download. New versions land on GitHub Releases — this page always links the latest.

Can I extend the agent?

Extensively: drop SKILL.md files into .nexus/skills, define slash commands, add project rules (AGENTS.md, CLAUDE.md, .cursorrules…), connect MCP servers (stdio/HTTP/SSE), and set allow/ask/deny permission policies per project.
